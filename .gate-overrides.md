## security-reviewer-F001 (multi-user auth / owner isolation on Kokugo progress)

**Disposition**: product-accepted exception (not a code multi-tenant implementation).

**Authority**: product owner confirmation 2026-08-03 — cloud is static with **no server**; only local runs `cmd/api` + progress.

**Canonical decision**: `DECISIONS.md` → **2026-08-03 — JS-131/132 security multi-tenant finding: user-accepted deployment exception**.

**Why not implement multi-user auth in this PR**:
- Cloud/portfolio (JS-018) has no Go server and no `/api/kokugo/**` learner-state write surface.
- Local API is audience-of-one; trust boundary is the local process (same as existing `read_log` / quiz progress).
- Multi-user identity isolation is deferred until a shared or internet-exposed API is intentionally adopted.

**Compensating controls** (must remain true):
- Progress writes require `ProgressStore.Enabled()` (sqlite local); static/null disables them.
- Server-enforced full-cycle completion, body size limit, stable public errors, artifact CAS (code-fixed this branch).

**Revocation**: if Kokugo progress is hosted for multiple users or on a public network, this exception is void — require auth + owner scoping before enablement.
